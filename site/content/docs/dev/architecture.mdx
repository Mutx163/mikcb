## 技术栈

| 层 | 选型 |
| --- | --- |
| 语言与 UI | Kotlin 2.4.21 + Jetpack Compose 1.12 |
| HyperOS 风格组件 | miuix 0.9.4 组件库（其中 `miuix-ui` 为本地 fork：`android/third_party/miuix-ui`） |
| 状态与数据 | `TimetableRepository` + 不可变设置模型 + Compose 状态提升 |
| 本地存储 | SharedPreferences（键名沿用旧版 `flutter.*` 前缀，覆盖安装不清数据） |
| 液态玻璃 | miuix-blur（`RuntimeShader` 效果链；不支持时降级实体卡片） |
| 扫码与二维码传输 | ML Kit Barcode Scanning + 自研多帧喷泉码（`QrFountainLt`） |
| 原生能力 | Android Notification、Foreground Service、AlarmClock、AppWidget |
| 构建与发布 | Gradle 9.8.2 / AGP 9.4.1 · GitHub Actions / GitHub Releases |

平台侧：compileSdk 37 / targetSdk 36 / minSdk 33，JDK 21，Kotlin 2.4.21。

## 分层结构

```
Compose UI（composeP1/pages：课表 / 日视图 / 设置 / 统计 / 关于）
        ↓
app 层（TimetableRepository、TimetableSettingsModel、各类 Dispatcher）
        ↓
领域服务（course / calendar / statistics / sync / transfer / weather / widgetdata）
        ↓
platform 层（SharedPreferences、SAF、WebDAV、Keystore、壁纸文件、截图监听）
        ↓
Android 原生（通知、前台服务、桌面小组件、超级岛）
```

页面和原生能力之间不再有跨语言桥：Compose 直接调用 Kotlin 模型与服务，系统能力按需直连 Android API。

## 超级岛实现要点

超级岛本质是 Android 焦点通知（promoted ongoing），小米 / HyperOS 在其上做了系统级展示。

- 由 `LiveUpdateService` 维护通知渠道与焦点通知状态
- 前提是 Android 16（`SDK_INT >= 36`）且系统允许发布 promoted ongoing notification
- 岛标签另受小米系机型判定限制，非小米 Android 16 设备只发普通常驻通知
- 通知与超级岛跟随当前课表切换，考试安排同样进入提醒链路

<Callout type="info">
  超级岛的显示分区有约定：摄像头左侧是通知 smallIcon，不承载文本；右侧是整条 critical text。改动预览组件时需要同步原生实现。
</Callout>

## 数据模型

课程的核心字段包括名称、简称、教师、地点、星期、起止节次、起止时间、颜色、周次范围、单双周标记与备注。

持久化以 SharedPreferences 为主（键名保留旧版 `flutter.*` 前缀，升级不清数据），备份导出为明文文件，WebDAV 同步在此基础上增加历史快照。
