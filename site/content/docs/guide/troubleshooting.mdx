---
title: 故障排查
description: 通知不响、超级岛不显示、导入失败、同步失败等问题的排查顺序。
---

按现象对号入座。大多数问题都出在系统权限或时间配置上。

## 收不到课前提醒

按顺序检查：

<Steps>
<Step>
**通知权限**：Android 13+ 需要显式授予。
</Step>
<Step>
**时间模板**：与本校作息是否一致，时间错了提醒自然不准。
</Step>
<Step>
**课表选择**：提醒跟随当前课表，确认选对了。
</Step>
<Step>
**电池优化**：设为「无限制」，否则后台被冻结后会延迟或丢失。
</Step>
<Step>
**自启动**：保证重启后提醒链路能自动恢复。
</Step>
</Steps>

<Callout type="warn">
  部分厂商 ROM 对后台管控较激进。即使开关全部打开，深度睡眠时仍可能被限制。这种情况建议改用**上课闹钟**兜底——它走系统时钟通道，即使应用被清理也会响。
</Callout>

## 超级岛不显示

1. 确认设备是小米 / HyperOS，且系统版本支持焦点通知
2. 开启**焦点通知 / promoted ongoing** 权限
3. 开启通知权限与自启动
4. 确认当前课表在当天有课

显示内容可以在设置中按需开关（课程名、简称、地点、倒计时、阶段文字）。

## 导入教务系统失败

- 学校可能尚未适配。适配脚本在 [qingyu_warehouse](https://github.com/Mutx163/qingyu_warehouse)，可查看是否已有你的学校
- 未适配时改用 [ICS 导入或 AI 识图](/docs/guide/import)
- 教务系统改版也会导致原有适配失效，可在仓库提 issue

## WebDAV 同步失败

依次检查：

- 服务器地址是否以 `https://` 开头
- 账号密码是否包含特殊字符
- 服务端是否限制了 WebDAV 方法
- 当前网络能否访问该地址

需要回滚时，在历史快照中选择此前的版本。详见[同步与备份](/docs/guide/sync-backup)。

## 桌面小组件不更新

- 检查电池优化是否限制了后台活动
- 移除小组件后重新添加
- 确认课表有变更（无变更时内容不会变）

## 数据丢失

- **换手机后为空**：确认是否导入过备份。若没有，回旧设备导出备份再迁移
- **误删课程**：用最近一次备份恢复，或在 WebDAV 历史快照中回滚
- **旧设备已清空**：无法恢复

<Callout type="warn">
  备份文件是唯一的恢复依据。建议每学期至少导出一次。
</Callout>

## 应用内更新检测不到新版本

关于页会读取 GitHub Releases。检测不到时：

- 确认网络可访问 GitHub
- 直接到 [Releases 页面](https://github.com/Mutx163/mikcb/releases)下载
- 正式包以 `arm64-v8a` 为主，确认设备架构匹配

## 还是没解决

带上设备型号、系统版本、应用版本和复现步骤，到 [GitHub Issues](https://github.com/Mutx163/mikcb/issues) 反馈。日志能显著提高定位效率。
