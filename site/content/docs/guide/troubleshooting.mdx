---
title: 故障排查
description: 通知不响、超级岛不显示、导入失败、同步失败、小组件不更新等问题的排查顺序与日志收集。
---

按现象对号入座。大多数问题都出在**系统权限**或**时间配置**上。

## 先查这三个

大多数问题都出在这三处，一分钟能看完：

<Steps>
<Step>
**开学日期**：设置首页顶部摘要卡显示的「当前第 N 周」和学校对不对得上。
不对就去[学期设置](/docs/guide/interface#学期与周次)改。
</Step>
<Step>
**时间模板**：设置 → 时间模板，节次起止时间是不是本校作息。
</Step>
<Step>
**通知权限**：Android 13+ 需要显式授予。没有它一切提醒都不存在。
</Step>
</Steps>

## 周次不对

**显示的「当前第 N 周」和学校不一样**

周次是拿**开学日期**推的，不是手机日历周。去设置 → 点顶部摘要卡 →
改开学日期，再点「同步当前周」对齐。

**单双周错位**

学校第一周没课时，导入时要在「课表第 1 周对应校历第几周」里往后调
（第一周没课就选第 2 周）。已经导入完了的话，改开学日期或重导一次。

## 收不到课前提醒

按顺序检查：

<Steps>
<Step>
**通知权限**：Android 13+ 需要显式授予。没有它一切提醒都不存在。
</Step>
<Step>
**时间模板与开学日期**：与本校作息是否一致，时间错了提醒自然不准。
重点看「设置」顶部摘要卡显示的当前周对不对。
</Step>
<Step>
**课表选择**：提醒跟随当前课表，确认选对了，且当天确实有课。
</Step>
<Step>
**是否在假期内**：法定节假日与自定义假期期间，提醒和小组件会隐藏课程。
</Step>
<Step>
**电池优化**：设为「无限制」，否则后台被冻结后会延迟或丢失。
</Step>
<Step>
**自启动**：保证重启后提醒链路能自动恢复。
</Step>
</Steps>

<Callout type="warn">
  部分厂商 ROM 对后台管控较激进。即使开关全部打开，深度睡眠时仍可能被限制。
  这种情况建议改用**上课闹钟**兜底——它走系统时钟通道，即使应用被清理也会响。
</Callout>

## 超级岛不显示

<Steps>
<Step>
确认设备是小米 / HyperOS，且系统版本为 **HyperOS 3.0.300 及以上**。
（设置里的「当前状态」会显示超级岛系统支持情况。）
</Step>
<Step>
开启**焦点通知 / promoted ongoing** 权限。
</Step>
<Step>
开启通知权限与自启动，电池设为「无限制」。
</Step>
<Step>
确认当前课表当天有课，且**不在假期范围内**。
</Step>
<Step>
进入**设置 → 超级岛与通知 → 自检**，发一条测试通知，
看「不上岛原因」里写了什么。
</Step>
</Steps>

显示内容可以在「上课前提醒显示」里按需开关（课程名、简称、地点、倒计时、阶段文字）。

<Callout type="warn">
  发送测试通知或选课测试后，**必须按 Home 键回到桌面**才能看到超级岛——
  停留在应用内时系统通常不弹。
</Callout>

### 常见「不上岛原因」

| 提示 | 处理 |
| --- | --- |
| 缺少通知权限 | 去系统设置授予通知权限 |
| 当前在假期范围内 | 到「设置 → 节假日标记」移除覆盖今天的假期 |
| 已注入预设课程但此刻不弹 | 若「上课前提醒」已关闭，岛会在课程真正开始后（约 1 分钟）才出现 |
| 已开启但系统暂未确认 | 重新开关一次焦点通知权限，或重启应用 |

## 导入教务系统失败

- **学校可能尚未适配**：适配脚本在 [qingyu_warehouse](https://github.com/Mutx163/qingyu_warehouse)，
  先看有没有你的学校。没有的话用导入页底部的「缺少学校？去反馈」提交
- **未适配时改用** [表格导入、ICS 导入或 AI 识图](/docs/guide/import)
- **教务系统改版**也会导致原有适配失效，在适配仓库提 issue
- **学校列表读不出来**：通常是网络问题。页面会提示尝试了几个镜像线路，
  可到「版本更新」里切换镜像后重试
- **需要更详细信息**：导出导入页里的**「课表导入执行日志」**再反馈

### 表格导入有行没导进来

会先弹「导入提醒」列出问题行与原因。点「继续导入」可跳过它们导入其余课程。

提示「未识别表格格式」说明表头对不上，用官方模板重填。

## WebDAV 同步失败

依次检查：

<Steps>
<Step>
**应用专用密码**：必须用坚果云「安全选项 → 添加应用密码」生成的密码，
**不是登录密码**。
</Step>
<Step>
**WebDAV 地址**：坚果云默认 `https://dav.jianguoyun.com/dav/`，
建议使用 HTTPS。
</Step>
<Step>
**账号密码是否含特殊字符**，以及是否复制进了多余空格。
</Step>
<Step>
**服务端是否限制了 WebDAV 方法**（自定义 WebDAV 时常见）。
</Step>
<Step>
**当前网络能否访问该地址**。
</Step>
</Steps>

需要回滚时，在云同步页的**「可恢复版本」**里选择此前的版本。
详见[同步与备份](/docs/guide/sync-backup)。

## 桌面小组件不更新

<Steps>
<Step>
检查**电池优化**是否限制了后台活动。
</Step>
<Step>
检查**精确闹钟权限**（设置 → 桌面小组件顶部会显示提示条）。
未授予时课程边界只能非精确刷新，卡片可能延迟更新。
</Step>
<Step>
**移除小组件后重新添加**。
</Step>
<Step>
确认课表确实有变更（无变更时内容不会变），且不在假期内。
</Step>
</Steps>

## 数据丢失

| 情况 | 处理方式 |
| --- | --- |
| **换手机后为空** | 确认是否导入过备份。若没有，回旧设备导出备份再迁移 |
| **误删课程** | 用最近一次备份恢复，或在云同步的可恢复版本里回滚 |
| **导入时覆盖了** | 「数据备份与迁移」支持撤销本次导入；云同步恢复后也提供撤销 |
| **旧设备已清空** | 无法恢复 |

<Callout type="warn">
  备份文件是唯一的恢复依据。建议每学期至少导出一次。
</Callout>

## 课表显示异常

**课程卡片上的字被截断**

填**课程简称**（3 字以内）。超级岛和小组件空间有限，长名一定会被截。
简称不会自动生成，要手动填（可以点「取前两字」）。

**卡片上的钟点和时间模板对不上**

这门课可能命中了**地点作息匹配**，或者单独指定了**副时间表**，
生效顺序见[名词与数据说明 → 时间相关](/docs/guide/glossary#时间相关)。
左侧时间列始终显示课表默认模板，卡片和详情以最终匹配结果为准。

**改了课程名，之前的备注和统计没了**

课程**以名称作为唯一标识**，改名等于新建一门课。想改显示效果请改简称。

**假期里超级岛不弹、小组件空白**

正常，法定节假日和自定义假期期间会隐藏课程，先查「设置 → 节假日标记」。
详见[常见问题 → 提醒与超级岛](/docs/guide/faq#提醒与超级岛)。

## 假期日期和学校的不一样

**现象**：学校的放假安排和国务院公布的不一致。常见的是**中秋国庆连休**，
比如 9 月 25 日放到 10 月 4 日，而 10 月 5 日～7 日学校已经正常上课——
但课表上那几天还是假期状态，课程被隐藏、提醒也不响。

应用内置的是全国统一数据，**不会自动知道你们学校的特殊安排**，需要手动覆盖。

<Steps>
<Step>
进入**设置 → 节假日标记 → 自定义假期**，点**「添加假期」**。
</Step>
<Step>
**名称**随意填（比如「补课」「秋季学期上课」），**起止日期**选需要上课的那几天
（上面例子里就是 10 月 5 日 ~ 10 月 7 日）。
</Step>
<Step>
**类型选「调休上班」**，保存。
</Step>
</Steps>

保存后这几天立刻恢复为上课状态：课程重新显示，**课前提醒、超级岛、
桌面小组件也会跟着恢复**。日期选错的可以在同一页编辑或删除。

<Callout type="info">
  **「调休上班」的优先级最高。**它专门用来表达「这天本来算假期，但我们上课」，
  所以能盖住法定假期。不用去删法定假期条目——只补需要上课的那几天就行。

  反过来也成立：如果学校**提前放假**（比法定早放几天），
  同样路径添加一条，类型选**「假期」**即可。
</Callout>

<Callout type="warn">
  **换机或重装后记得确认。**自定义假期会随 **WebDAV 云同步**一起走，
  但**本地备份文件（完整备份导出）里不含它**——用备份文件迁到新设备时，
  需要在「设置 → 节假日标记」重加一次。
</Callout>

## 应用内更新检测不到新版本

关于页读取的是 GitHub Releases。检测不到时按顺序查：

<Steps>
<Step>
**网络**：确认当前网络能访问 GitHub。访问不了就先切国内线路。
</Step>
<Step>
**下载渠道**：在「版本更新 → 高级选项」里切换下载方式
（蒲公英 / GitHub / GitCode），或切到国内下载 + 镜像线路。
</Step>
<Step>
**镜像线路**：点「测速并推荐」让应用自动挑最快的镜像。
</Step>
<Step>
**预发布通道**：只想收正式版的话，确认「测试版检测」是关闭的。
</Step>
<Step>
**设备架构**：正式包以 `arm64-v8a` 为主，确认设备架构匹配。
</Step>
<Step>
仍不行就直接到 [Releases 页面](https://github.com/Mutx163/mikcb/releases)
手动下载，或从「关于软件 → 问题反馈」反映。
</Step>
</Steps>

下载渠道与镜像的完整说明见[更新与支持 → 怎么更新应用](/docs/guide/about#怎么更新应用)。

## 局域网编辑连不上

<Steps>
<Step>
确认手机和电脑在**同一个局域网**。页面显示「未检测到局域网 IP」时先查 WiFi。
</Step>
<Step>
宿舍 WiFi 禁止设备互访时，用**手机开热点、电脑连该热点**。
</Step>
<Step>
确认地址完整（含端口），PIN 输入正确。扫页面上的二维码能省掉手输。
</Step>
<Step>
还是不行就把「离开后保持开启」打开再试，避免回到设置页时被自动关掉。
</Step>
</Steps>

## 情侣课表看不到对方的课

<Steps>
<Step>
**槽位是不是重复了**：用坚果云拉取时，双方**必须选不同槽位**（一个 1、一个 2）。
这是最常见的原因。
</Step>
<Step>
对方点过**「上传我的课表到坚果云」**没有？只有上传了，你才拉得到。
</Step>
<Step>
手动传文件的话，确认对方导入的是**你导出给他的那份文件**，且导入成功了
（提示「已导入对方课表」）。
</Step>
<Step>
**周次偏移**不为 0 时会读对方的另一周。先设回「无偏移」确认能不能看到。
</Step>
<Step>
两边**开学日期不同**也会对不齐，各自先核自己的当前周。
</Step>
</Steps>

<Callout type="info">
  对方课表是**只读**的——只能查看备注，不能编辑或调课。这是设计如此，不是 bug。
</Callout>

## 二维码传输中断

| 提示 | 处理 |
| --- | --- |
| 二维码传输已超时 | 重新开始，中途不要切走 |
| 检测到不同传输内容 | 只对准一台设备 |
| 二维码数据解码失败 | 拉远距离或调高亮度后重新开始 |
| 传输校验失败 / 数据解压失败 | 重新开始一次 |
| 接收数据超过资源上限 | 数据太大，改发「当前课表」或用备份文件 |

## 统计数字对不上

- **刚加的课没算进去**：确认已保存、周次范围覆盖当前周、当前课表选对了
- **切换课表后变了**：正常，统计跟随当前课表。用「课表对比」看多张之间的差别
- **成就没解锁**：点徽章看具体条件和当前进度（如「64/100」），
  条件见[课程统计 → 成就徽章](/docs/guide/statistics#成就徽章)
- **热力图看不懂**：按星期与节次着色，颜色越深表示该时段课程越多

## 收集日志再反馈

反馈问题前请先收集日志，能大幅提高定位效率。

| 日志 | 位置 | 适合什么问题 |
| --- | --- | --- |
| **应用日志** | 设置 → 关于 → 关于软件 → 应用日志 | 更新、导入、通知、页面、崩溃 |
| **超级岛日志** | 自检页 → 「导出并分享日志」 | 超级岛没弹出、状态异常 |
| **状态快照** | 自检页 → 导出（含完整原生字段） | 需要核对原生诊断字段 |
| **教务导入执行日志** | 导入页 → 「课表导入执行日志」 | 教务系统导入失败 |

### 诊断页怎么用

设置 → 关于 → 诊断。支持**结构化**与**原文**两种查看方式：

- 按等级筛选：全部 / 错误 / 警告 / 信息 / 调试 / 详细
- 按时间排序：正序 / 倒序
- 实时更新中，新日志会自动追加
- 可加载更早日志、复制日志、导出日志、清空日志

<Callout type="info">
  应用日志记录可以关闭。关闭后不再新增，页面会提示「记录已关闭，下方为历史日志」。
  排查问题时记得先打开记录、复现问题、再导出。
</Callout>

## 还是没解决

带上**设备型号、系统版本、应用版本、复现步骤和日志**，到
[GitHub Issues](https://github.com/Mutx163/mikcb/issues) 反馈。
也可以在应用内「关于软件 → 问题反馈」找到 Issue 入口与社区渠道。
