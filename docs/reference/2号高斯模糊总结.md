# 2号高斯模糊总结

> 主题：HyperOS 标题栏 CFH（Cached Frosted Header）高斯模糊——现状诊断、方案对比与推荐实现路径。  
> 相关代码：`lib/ui/hyperos/frosted/`、`lib/services/frosted_blur_service.dart`、`lib/ui/hyperos/hyperos_page.dart`  
> 日期：2026-07-06

---

## 1. 我们在做什么

mikcb 设置首页等页面的标题栏，目标是复刻 HyperOS 系统设置：**列表滚到标题栏下方时，栏内呈现毛玻璃（模糊 + 半透明 scrim）**。

当前实现不是 `BackdropFilter` 实时采样，而是 **CFH 位图管线**：

```
RepaintBoundary.toImage(0.72×)
  → 裁标题条（含 kernel bleed）
  → FrostedBlurService.blurImage（Android 原生 / Dart fallback）
  → RawImage + tint 叠在 FHeader 下
```

产品范围（已有约定）：

| 条件 | 行为 |
|------|------|
| Android + `overlayHeader: true` + 路由 settled | 真模糊 |
| `HyperosSubpage` 默认（`overlayHeader: false`） | 仅 tint，无 capture |
| 课表首页（`overlayHeader: false`） | 仅 tint |
| iOS / Web | 仅 tint |

## 2. 现状问题（为什么不跟手）

### 2.1 根因：显示策略与滚动状态脱节

```dart
// frosted_header_controller.dart
ui.Image? get displayImage => _blurredImage ?? _previewImage;
bool get isPreviewActive => _blurredImage == null && _previewImage != null;
```

- 首次模糊成功后 `_blurredImage` 常驻。
- 滚动时 `_applyPreview(strip)` 已算出**位置正确**的 sharp 裁切，但 `displayImage` **仍优先旧 `_blurredImage`**。
- `previewActive` 的 tint 加成也不会触发。

**结果**：手指在动时标题栏「粘」在上一帧模糊图上；松手或减速后某次异步模糊才追上——体感为「滑动结束才有变化」。

### 2.2 放大因素

| 因素 | 说明 |
|------|------|
| 模糊成本高 | 每帧 `toByteData` → 平台通道 → 原生 blur → 重建 `ui.Image`，单次数十～上百 ms |
| generation 作废 | 快滑时大量 blur 任务算完即丢，界面长期停在旧帧 |
| `_pendingUpdate` 泄漏 | 节流跳过的事件，只在 blur **成功**时消费；作废路径不补调度 |
| idle 全量刷新 | `ScrollEnd` + **200ms** 才 `scheduleFullRefresh`，停手后延迟明显 |
| 全屏重捕节流 | 滚动中 full capture 限 **140ms**，lazy list 新内容在旧快照里不存在 |
| 双重滚动监听 | `HyperosListView` 与 `_buildCapturableBody` 各转发一次 `ScrollNotification` |

### 2.3 因果链

```
滚动 → 新 preview 就绪 → 界面仍画旧 blurred → 异步 blur 排队/作废
     → ScrollEnd + debounce → 全屏重捕 → 最终 blurred 更新
     → 用户感知：不跟手，停手才变
```

## 3. 候选方案对比

### 方案 A：实时 `BackdropFilter` / `ImageFiltered`

在标题栏区域直接对下层 Widget 做 GPU 实时模糊。

| 优点 | 缺点 |
|------|------|
| 天然跟手，无需快照 | Android 上全屏 ListView + BackdropFilter 极易掉帧 |
| 实现简单 | 与 CFH 架构冲突，需大改页面层级 |
| | 模糊区域外缘、透明像素行为难控 |

**结论**：不适合作为 mikcb 主路径（设置页列表重、目标中低端机）。

---

### 方案 B：维持 CFH，滚动与静止统一走「裁条 + 每帧 blur」

在现有管线上只调节流参数，仍指望每帧产出 blurred 位图。

| 优点 | 缺点 |
|------|------|
| 改动面小 | **算力上不可行**：blur 吞吐远低于 60fps |
| | 不解决 `displayImage` 优先级问题 |
| | 快滑时 generation 雪崩依旧 |

**结论**：不能作为终态方案；可作为修 bug 后的补充，不能单靠它解决跟手。

---

### 方案 C：两阶段渲染（滚动 preview / 静止 blur）——**推荐**

在 **保留 CFH 架构** 的前提下，引入明确的**交互相位**：

| 相位 | 显示 | 后台工作 |
|------|------|----------|
| **Scrolling**（`ScrollStart`～`ScrollEnd`） | **优先 `_previewImage`**（sharp 裁切，略加深 tint） | 仅裁条，**不启动 blur**（或极低频） |
| **Settled**（`ScrollEnd` + 短 debounce） | 切回 `_blurredImage` | 一次 full capture（如需）+ **单次 blur** |

核心显示逻辑改为：

```dart
// 概念示意，非最终实现
ui.Image? get displayImage {
  if (_isScrolling) return _previewImage ?? _blurredImage;
  return _blurredImage ?? _previewImage;
}
```

| 优点 | 缺点 |
|------|------|
| 滚动跟手（裁切 cheap，可达 ~60fps） | 滚动中视觉为「清晰内容 + 厚 tint」，非最终毛玻璃 |
| 静止后恢复 HyperOS 毛玻璃质感 | 需维护 `_isScrolling` 状态与相位切换 |
| 模糊次数从 O(滚动帧) 降到 O(滚动段) | 相位切换瞬间需避免闪烁（可 cross-fade 或保持 tint 连续） |
| 与现有 Android 原生 blur、降采样捕获兼容 | |

**结论**：**最合适的主方案**——在性能、视觉、改动量之间平衡最好。

---

### 方案 D：滚动也用降质 blur（半分辨率 / 更小 sigma）

Scrolling 相仍做 blur，但 sigma 减半或再降 `headerPixelRatio`。

| 优点 | 缺点 |
|------|------|
| 滚动中也有「一点糊」 | 仍受 native RGBA 往返限制，跟手提升有限 |
| | 两档视觉切换更复杂 |

**结论**：可作为方案 C 的 **可选增强**（中高端机 A/B），不作为默认必做项。

---

### 方案 E：全面改为 Shader / Impeller 自定义后处理

**结论**：投入产出比过低，**不推荐**。

---

## 4. 推荐方案：方案 C 细化

### 4.1 设计原则

1. **跟手优先**：滚动时用户看到的是**位置正确**的内容，哪怕暂时不是高斯模糊。
2. **模糊降频**：模糊是昂贵操作，只在 **settled** 时做一次（或滚动中最多每 140ms 一次可选增强）。
3. **状态机清晰**：`idle | scrolling | settling` 三态，避免 `displayImage` 隐式优先级。
4. **最小侵入**：不改 `FScaffold` / 路由结构，只动 `FrostedHeaderController` + 少量 shell 逻辑。

### 4.2 状态机

```
                    ScrollStart
            idle ──────────────► scrolling
              ▲                    │
              │                    │ ScrollEnd
              │                    ▼
              └──── debounce ─ settling
                     (full capture + blur)
```

| 状态 | `captureEnabled` 行为 | `displayImage` | blur 任务 |
|------|----------------------|----------------|-----------|
| `idle` | 正常 | `blurred ?? preview` | 允许 |
| `scrolling` | 正常 | **`preview ?? blurred`** | **暂停新任务** |
| `settling` | 正常 | 先 `preview`，blur 完成后 `blurred` | **一次** full refresh |

- `settling` debounce 建议 **80～120ms**（现 200ms 偏长，可缩短；仍保留大于一帧以避免 bounce 连触）。
- 路由转场期间沿用现有 `_cfhReady` / `_blurSettled` 门控，**不**在转场中进入 scrolling 优化。

### 4.3 必做修复清单（与状态机正交）

| # | 项 | 文件 | 说明 |
|---|-----|------|------|
| 1 | 滚动相位 `displayImage` | `frosted_header_controller.dart` | 实现 §4.2 优先级反转 |
| 2 | scrolling 时跳过 `_blurStripAsync` | 同上 | 或入队后在 scrolling 结束统一 flush |
| 3 | `_pendingUpdate` 在 generation 作废时也 flush | 同上 | 避免快滑后永不更新 |
| 4 | 去掉重复 scroll 监听 | `hyperos_page.dart` 或 `HyperosListView` | 只保留一层 `NotificationListener` |
| 5 | `ScrollEnd` 立即 schedule crop+preview | `frosted_header_controller.dart` | 不等到 idle timer 才第一次更新 preview |
| 6 | idle full refresh 保留但缩短 debounce | 同上 | 负责 lazy list 新 tile 进快照 |

### 4.4 视觉连续性

滚动相位用已有 `previewTintBoost`（+0.12 alpha）掩盖「未模糊」感：

```dart
// hyperos_blurred_header.dart — 已有
if (withBlur && previewActive) {
  tintAlpha = (tintAlpha + previewTintBoost).clamp(0.0, 0.72);
}
```

需将 `isPreviewActive` 扩展为：**scrolling 相位** 或 **`_blurredImage == null`** 时为 true（不再要求 blurred 为空）。

settling 完成后 `previewActive = false`，blurred 淡入可通过保持 tint 不变避免跳变（当前 stack 是直接换图，一般可接受；若闪烁再加 1～2 帧 cross-fade）。

### 4.5 参数建议（默认值）

| 参数 | 现值 | 建议 | 理由 |
|------|------|------|------|
| `_scrollUpdateThrottle` | 16ms | **保持** | 与屏幕刷新对齐 |
| `_scrollFullThrottle` | 140ms | **保持** | 滚动中 full capture 仍贵 |
| `_idleDebounce` | 200ms | **80～120ms** | 缩短停手后最终模糊延迟 |
| `blurSigma` | 10 | **保持** | 静止相位视觉已验证 |
| `headerPixelRatio` | 0.72 | **保持** | 预览裁切可承受 |

### 4.6 不改动范围

- **不**把子页默认改为 `overlayHeader: true`（性能与产品范围不变）。
- **不**在 iOS 强开 live blur（维持 tint-only）。
- **不**删除 Android 原生 `FrostedBlur.kt` 路径（静止相位仍用）。
- **不**引入 `BackdropFilter` 作为默认实现。

## 5. 实施顺序（建议 PR 切分）

### PR-1：跟手修复（高优先级，低风险）

- 状态机 + `displayImage` / `isPreviewActive` 修正
- scrolling 暂停 blur
- `_pendingUpdate` flush 修复
- 去掉双重 scroll 监听

**验收**：设置首页快速滑动时，标题栏下方列表文字/色块**位置**与手指同步；停止后 ≤150ms 内变为毛玻璃。

### PR-2：settle 体验打磨（中优先级）

- 缩短 idle debounce
- `ScrollEnd` 立即 crop preview
- （可选）settling 单次 blur 前强制 full capture

**验收**：慢滑、快滑、fling 后无长期错位；lazy 区段滚入新卡片后停手，标题栏内容正确。

### PR-3：可选增强（低优先级）

- 中高端机 scrolling 半质 blur（方案 D）
- debug 面板暴露 `blurSigma` / debounce 调参

## 6. 测试要点

| 场景 | 期望 |
|------|------|
| 设置首页慢速滑动 | 标题栏内容实时跟随，略厚 tint |
| 快速 fling | 不卡死、不长期停在旧图；停手后模糊更新 |
| 连续来回滑 | 无内存涨、无 `ui.Image` 泄漏告警 |

## 7. 一句话结论

**最合适方案 = 保留 CFH 位图架构 + 方案 C「滚动 preview、静止 blur」两阶段渲染**，并修复 `displayImage` 优先级、pending 调度与重复滚动监听。

这样既能在滚动时跟手（cheap 裁切），又能在停手后呈现 HyperOS 级毛玻璃（expensive 模糊只做一次），且不需要推翻现有 Android 原生模糊与页面结构。
