# v3.0.0-1 升级清单（Flutter 2.1.4.x → Compose 3.0.0 预发布）

> 用途：发布当天与真机验收照这张表走。**只写「怎么确认」，本文件不触发任何发布动作。**
> 场景：手机上已装 Flutter 版 v2.1.4.1（versionCode 100140），直接覆盖安装 v3.0.0 预发布包（`versionName=3.0.0-0`，versionCode 必须严格大于 100141，见 §2.2），不卸载。
> 核对基准：分支 `compose-merge`，核对时 HEAD `4a21d0ae4`（2026-11-10，行号按内容锚点复核到 `0e62b143c`）；旧版依据 tag `v2.1.4.1`。若后续提交移动文件，以引用的内容为准。
> 版本口径：对外 `versionName=3.0.0-0`、tag `v3.0.0`（App 内显示 3.0.0）；内部文档统一 `3.0.0-1` 前缀。

## 0. 一句话结论

| 问题 | 结论 |
|---|---|
| 跨大版本（2.1.4.x → 3.0.0）能不能直接覆盖安装 | 能：`applicationId` 未变、签名同一把、versionCode 严格递增；手机需 Android 13 及以上 |
| 课表 / 日程 / 考试 / 待办 | 不丢，都在同一份档案 JSON 里，键名一个没改 |
| 设置（主题 / 语言 / 外观） | 不丢，档案内嵌的整份设置写回时有合并保护 |
| 壁纸 | 不丢，老图按绝对路径继续读 |
| 桌面小组件 | 已有卡片继续显示，升级时自动重画 |
| 通知渠道（静音 / 重要级别） | 不重置，渠道 id 一个没改 |
| 网盘 / 情侣同步密码 | 要重输一次，**有提示** |
| 教务「记住登录」 | 会空，要重输，**没有提示**（见 §5） |
| 回退旧版 | 不能直接点装旧包（系统拒绝降级），见 §6；**升级前必须先导出备份** |

> 本版是**预发布**：`versionName=3.0.0-0` 带 `-` 段，CI 自动判 prerelease（`.github/workflows/android-build.yml:136-140`）；`-0` 会被剥掉，对外 tag 是 `v3.0.0`（`:70`），App 内显示 3.0.0。发版动作仍压着，等用户真机测完发话。

## 1. 跨大版本升级（2.1.4.x → 3.0.0）说明

这次不是小版本：整个 App 从 Flutter 换成 Compose 重写。对「升级」这件事只有四条要记住：

1. **可以直接覆盖安装，不用卸载**：`applicationId` 仍是 `com.mutx163.qingyu`（`android/app/build.gradle:58` ↔ 旧 tag `:45`），签名同一把，versionCode 严格大于旧包（§2.2）。
2. **本地数据按老键原样读**：课表、日程、考试、待办、设置、壁纸都在旧版那份 `FlutterSharedPreferences` 里，键名带 `flutter.` 前缀、一个没改（`.../platform/PrefsKeyValueStore.kt:160`、`.../app/KeyValueStore.kt:97-100`；旧键字面量见 tag `lib/services/storage_service.dart:18-23`）。没有数据库，不存在「大版本要迁移数据库」。
3. **教务「记住登录」要重输一次**：旧凭据在新版读不出来，已拍板不补提示，靠更新日志告知（`docs/releases/v3.0.0.md` 有「从旧版升级后需要重新登录一次教务」）。
4. **升级前先导出 `.mikcb` 备份**：回退只能卸载，卸载会清壁纸与凭据；备份是唯一兜底（§2.4）。

## 2. 升级前（发布方，约 5 分钟）

1. **签名必须是同一把钥匙**：
   - 新包：`apksigner verify --print-certs mikcb-3.0.0-arm64-v8a.apk`，记下 `SHA-256 digest`。
   - 手机上已装的：`adb shell dumpsys package com.mutx163.qingyu` 里的 `signatures`（需用户允许连设备，只读）。
   - 两串必须一致。仓库里只能核到「两版用同一份 `key.properties` / 同名 CI secret」，**secret 的值仓库里看不到**，所以这一条只能现场比。
2. **版本号**：新包 `versionCode` 必须**严格大于 100141**（100140 是已装旧包，100141 是此前按 2.1.4-2 备过的自测值，两个都要能盖住），即 `versionCodeBase ≥ 142`；本次已拍定 `versionCodeBase=150` ⇒ **100150**（公式：`android/app/build.gradle:69` 的 `+100000`）。出包后用 `aapt2 dump badging <apk>` 复核实际值。
3. **系统版本**：`adb shell getprop ro.build.version.sdk` 必须 **≥ 33**（Android 13）。minSdk 这版从 26 抬到了 33，Android 12 及以下整机装不上。
4. **让用户在旧版里先导出一份备份**：设置 → 云备份 / 数据备份，把 `.mikcb`（或 JSON/CSV）导出到手机外的安全位置。
   - 这是**唯一能兜住「必须卸载才能回退」的底牌**；卸载 App 会连壁纸文件一起清掉。
5. **记录升级前状态**（都只读）：
   - 通知渠道：`adb shell dumpsys notification --noredact` 里 `com.mutx163.qingyu` 各渠道的 importance；
   - 桌面截图：10 类小组件各留一张（清单见 §4 第 9 项）；
   - 首页截图：当前壁纸与主题。

## 3. 覆盖安装（不卸载）

1. 用系统文件管理器 / 安装器点新 APK，正常覆盖安装；**不要点「卸载」**。
2. 报「应用未安装 / 签名不一致」→ 立刻停手，不要卸载，回到 §2.1 查签名。
3. 报「版本低于当前版本」→ 装错包或 versionCode 没算对，回 §2.2。

## 5. 已知变化（不是 bug，别当故障报）

1. **网盘 / 情侣同步密码要重输一次**：旧密文在 `FlutterSecureStorage`，新版换成自己的密文键，检测到旧键会弹一次提示（`LegacyCredentialProbe.kt:39-50`、`CloudSyncControllerPage.kt:107-119`）。输完即恢复，数据没丢。
2. **教务「记住登录」静默清空（已拍板：不补提示）**：旧值同样在 `FlutterSecureStorage`，新版读普通 prefs 且用另一把密钥；账号密码为空是预期。发版前不再动教务导入代码，由更新日志统一告知——`docs/releases/v3.0.0.md` 已含「从旧版升级后需要重新登录一次教务」；验收按 §4 第 14 项重输一次即恢复。
3. **小组件点击不再按绑定课表分流**：旧版点击 Intent 带 `appWidgetId`，新壳不读这组 extra，只按默认主页打开（`TodayWidgetSupport.kt:1817`、`NotificationLaunchTarget.kt:79-91`）。卡片刷新不受影响。
4. **启动页组件换了**：`.MainActivity` → `.pages.PagesShellActivity`。系统桌面图标按 MAIN/LAUNCHER 动态解析不受影响；只有用户手动「添加到桌面」的快捷方式指向旧组件会失效。
5. **壁纸分两个目录**：老图在 `app_flutter/wallpapers`，新版选的新图写 `files/wallpapers`（`ManagedWallpaperStore.kt:26-27`）。老图按绝对路径照常显示，只是回收 / 统计只认新目录，不影响使用。

## 6. 回退方案（先看代价再动手）

系统不允许版本号下降，直接点装 v2.1.4.1 会被拒（`INSTALL_FAILED_VERSION_DOWNGRADE`）。两条路：

- **A. 保数据回退**（需 USB 调试 + 同一把签名）：
  `adb install -r -d mikcb-2.1.4.1-arm64-v8a.apk`
  `-d` 允许降级、`-r` 保留数据；旧版仍能读新版写下的数据（同一 schema=1），旧版自己的 `FlutterSecureStorage` 密文也还在，密码不用重输。
- **B. 普通回退（只能卸载再装）**：
  卸载会清空全部本地数据（课表、壁纸文件、凭据），必须先用 §2.4 导出的备份恢复；恢复后网盘 / 教务密码仍需重输。

回退后**不要**删掉备份文件；确认新版问题定位完再清理。

## 7. 为什么数据不会丢（证据索引）

| 事实 | 证据 |
|---|---|
| 同包名 | 旧：tag `android/app/build.gradle:45`；新：`android/app/build.gradle:58`，都是 `com.mutx163.qingyu` |
| 版本号递增 | 旧 `2.1.4-1+140`（tag `pubspec.yaml:4`）+ 偏移（tag `android/app/build.gradle:51`）= 100140；新 `versionName=3.0.0-0`、`versionCodeBase=150`（`android/version.properties`）+ `android/app/build.gradle:69` = 100150，大于旧包 100140 与此前 2.1.4-2 的 100141 |
| 非三段 tag 的映射 | `3.0.0-0` 的 `-0` 被 CI 剥掉 ⇒ tag `v3.0.0`（`.github/workflows/android-build.yml:70`）；APK 的 versionName 由 tag 覆盖为 3.0.0（`:201`） |
| 预发布判定 | `android/version.properties` 的 `versionName` 含 `-` ⇒ CI 置 `IS_PRERELEASE=true`（`.github/workflows/android-build.yml:136-140`） |
| 旧包是单 ABI 单包 | tag `.github/workflows/android-build.yml:221`，无 `--split-per-abi`，不存在「按 ABI 乘过的大号」 |
| 同一个存储文件与前缀 | `android/app/src/main/kotlin/com/mutx163/qingyu/platform/PrefsKeyValueStore.kt:160`（`FlutterSharedPreferences`）、`.../app/KeyValueStore.kt:97-100`（`flutter.` 前缀） |
| 旧版键名逐字相同 | tag `lib/services/storage_service.dart:18-23` |
| 课表 / 日程 / 考试 / 待办同格式 | `.../core/TimetableProfile.kt:58-70,82-103` ↔ tag `lib/models/timetable_profile.dart:69-77` |
| 档案内嵌 250+ 键设置不被冲掉 | `.../app/TimetableStore.kt:287-317`（旧 settings 铺底再覆盖） |
| 旧单键 `courses` 不覆盖已有档案 | `.../app/TimetableRepository.kt:179-185`（`if (profiles.isEmpty())` 里才 bootstrap） |
| 全局设置自动播种、坏盘有回落 | `android/app/src/test/kotlin/com/mutx163/qingyu/app/UpgradeScenarioTest.kt`（7 格升级矩阵） |
| 引导标记照旧读 | `.../pages/guide/StartupFlowPreferences.kt:29-34` |
| 两版都没有数据库 | 旧 tag `pubspec.yaml:20,41,44` 只有 shared_preferences / path_provider / flutter_secure_storage；新版依赖无 room/sqlite/datastore |
| 10 个小组件类名与绑定存储没变 | tag `android/app/src/main/AndroidManifest.xml:301-409` ↔ 现 `:393-501`；`.../HomeWidgetStorage.kt:14`；`WidgetBindingStore` 从 tag 到现在无 diff |
| 升级时自动重画卡片 | `.../HomeWidgetRefreshReceiver.kt:12-25`（`MY_PACKAGE_REPLACED`）；`.../WidgetRefreshHost.kt:53` + `.../UmengApplication.kt:32` |
| 通知渠道 id 没改 | `LiveUpdateService.kt:50-51`、`ExamReminderScheduler.kt:29`、`WeeklyReportScheduler.kt:29`、`LanEditForegroundService.kt:16`（与 tag 同值） |

## 8. 旧目录处置（一条都别清）

- **不要清**：`shared_prefs/`（全部数据）、`app_flutter/`（壁纸原图、超级岛图标）、`files/`（日志、新版壁纸）。
- **可以清**：`cache/`，但清了既没风险也没收益。
- 「手机管家 / 深度清理 / 应用专清」不要清本应用数据；卸载前一定确认 §2.4 的备份已导出。
