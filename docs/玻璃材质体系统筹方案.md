## 一、为什么现在会乱：三个轴同时控制同一件事

| 轴 | 存储字段 | 现状 |
|---|---|---|
| ① 全局材质 | `frostedGlassMode` + `frostedBlurEnabled` | 4 档：实体 / 高斯 / 柔光 / 液态 |
| ② 作用范围 | 6 个 `liquidGlass*Enabled` | **仅在全局=液态时渲染**，柔光完全读不到 |
| ③ 表面自有选择器 | `homeChromeGlassMaterial`(3档)、`glassDockStyle`(2档)、`courseCardSurfaceStyle`(2档) | 与①重叠，**同一表面被两个轴管** |

②③ 打架之处就是首页玻璃带和底栏：它们既有自己的选择器，又被全局材质遥控。
而柔光只在**弹层类**写了分支（全项目只有 3 个文件认 `softGlass`，认 `liquidGlass` 的有 12+），
于是表现为「柔光范围比液态小」。

## 二、三个实锤缺陷（不是「少覆盖几个表面」那么简单）

### 缺陷 1：柔光绕过「作用范围」开关（语义不一致）

`lib/ui/hyperos/frosted/liquid_glass_degradation.dart:102-120`：

```dart
static bool familyFallsBackToSolid(BuildContext context, {required bool liquidGlassFamilyEnabled}) {
  if (shouldDegrade(context)) return true;
  final mode = FrostedAppearanceScope.maybeOf(context)?.appearance.glassMode;
  if (mode != FrostedGlassMode.liquidGlass) {
    return false;   // ← 柔光走到这里直接 false，家族开关被无视
  }
  return !liquidGlassFamilyEnabled;
}
```

且 `hyperos_sheet.dart:274` / `hyperos_select.dart:629` 的柔光分支排在家族判定**之前**，
所以：全局=柔光时，6 个作用范围开关**全部失效**，柔光无条件生效。

### 缺陷 2：底栏完全无视全局材质（`_kStockDockGlass` 硬编码 true）

`lib/screens/timetable_screen.dart:177`：`static const bool _kStockDockGlass = true;`

于是 `:6862` 的 `useLiquidGlass = !_kStockDockGlass && ...` **恒为 false**，
`:6910` 的 `settings: _kStockDockGlass ? stockBottomBarGlass : (...)` 恒取包原版材质。
底栏真实材质只有一条通路：`:6882` 的 `if (settings.glassDockStyle == DockGlassStyle.soft)`。

**结论：全局 4 档材质对底栏零影响**。选柔光时底栏会变柔光，不是因为柔光覆盖了底栏，
而是因为 `applyGlassModeChoice` 顺手写了 `glassDockStyle: DockGlassStyle.soft`
（`lib/models/glass_mode_choice.dart:53-57`）——是一个 setter 的副作用。

连带后果：全局选「实体卡片」（`applyGlassModeChoice` 写 `glassDockStyle: liquid`）时，
底栏仍是 `stockBottomBarGlass`（blur 3 / thickness 30 / 色散 0.3）的**折射玻璃**，
与引导页「所有表面回落实体卡片」的承诺不符。

### 缺陷 3：首页玻璃带的 3 档选择器会被全局液态静默架空

`lib/widgets/home_page_region_blur.dart:292-296`：

```dart
static bool _homeChromeUsesLiquid(FrostedAppearance appearance) {
  return appearance.homeChromeGlassMaterial == 'liquid' ||
      (appearance.glassMode == FrostedGlassMode.liquidGlass &&
          appearance.liquidGlassHomeChromeEnabled);   // 默认 true
}
```

`kDefaultLiquidGlassHomeChromeEnabled = true`，所以：全局选液态 → 课表页那 3 档选择器
**用户改不动**（选了 progressive 顶栏照样折射）。柔光没有这条兼容分支，顶栏回落 inspire 渐进模糊。

### 附带：引导页无法表达柔光

`lib/screens/user_guide_screen.dart:1158-1164` 只有 3 档（gaussian/liquidGlass/solid），
`_guideVisualEffectOf` 对 softGlass 返回 `gaussian`——全局选了柔光，引导页**显示「高斯模糊」被选中**。
`_applyVisualEffect`（:795）也没有 softGlass 分支。

## 三、目标模型：两层 + 固定的表面能力约束

核心原则：**1 个全局材质 + 1 组「跟随/不跟随」开关 + 少量硬性能力约束**，
不再允许「每个表面各自挑材质」。

### 第一层 · 材质（全局唯一选择器，4 档）

| 档位 | 技术 | 成本阶梯 |
|---|---|---|
| 实体卡片 | 不透明填充 | 免费 |
| 高斯模糊 | BackdropFilter + tint | 低 |
| 柔光玻璃 | Blur + 蒙层（无 shader） | 中 |
| 液态玻璃 | 折射 shader | 高 |

### 第二层 · 作用范围（复用现有 6 个开关，语义泛化）

- 出现在材质 ∈ {柔光, 液态} 时（**高级材质**才需要作用范围）
- 开 = 该表面使用**当前全局高级材质**
- 关 = 该表面回落**实体卡片**
- **不**降级为高斯——沿用 2026-09-11 已定稿的液态语义，只是把「液态玻璃作用范围」
  泛化成「高级材质作用范围」，**判定逻辑零改动，只是不再限定 liquidGlass**
- 柔光与液态**共用同一组**开关（不复制成 12 个）

### 第三层 · 表面能力约束（不是冗余，是硬限制）

- 课程卡：只有 `solid` / `gaussian`。课卡数量多、尺寸小，做折射/柔光没有意义且昂贵——**保留**
- 顶栏模糊风格：`progressive` / `gaussian` 是**衰减形态**（上浓下淡 vs 均匀+收边），
  与材质技术**正交**。应作为独立维度保留，不再和材质混在一个选择器里

## 四、逐表面落位

| # | 表面 | 今天·液态 | 今天·柔光 | 目标 |

| 5 | 玻璃坞底栏 | 受开关（**死代码**） | 靠另一套开关 | **删除独立开关**，跟全局材质 + 作用范围 |

| 位置 | 改前 | 改后 |

**主设置页回到「1 个选择器」**。

## 六、能消除的组合爆炸

改前可达且令人困惑的组合：

- `顶栏材质=liquid` + 全局=高斯 → 同时存在 2 种材质
- `底栏材质=soft` + 全局=高斯 → 同上
- 全局=液态 + `顶栏材质=progressive` → 选择器被静默架空
- 全局=实体卡片 → 底栏仍是折射玻璃

改后：**至多 1 种高级材质 + 实体卡片例外 + 课卡二元选择**。
「另一种玻璃」不再可能同时出现，只可能「有 / 没有高级材质」。

## 八、明确不做（仍然成立）

- ❌ 不给柔光复制另一套 6 个开关（12 个开关是灾难）
- ❌ 不改任何持久化 JSON 键、不动 `frostedGlassMode` 枚举值（免数据迁移）
- ❌ 不把「关闭作用范围」改成「降级高斯」（推翻已定稿语义）
- ❌ 不改 Dart 字段名（`liquidGlass*Enabled` → `advancedMaterial*`）：
  纯可读性收益，但要动约 40 处，多 Agent 并行下合并冲突成本 > 收益，**推迟**

## 九、遗留 / 后续可做

1. **真机走查**：柔光顶栏玻璃带是新增材质（此前从未在顶栏出现过），
   建议在深色 / 亮色壁纸上各看一次边缘光与墨色极性。
2. **底栏柔光观感**：底栏现在由全局材质驱动，全局切柔光时底栏即变雾面胶囊
   （此前也能，但当时还叠加了 `glassDockStyle` 这个第二轴）。
3. 字段改名（`liquidGlass*` → `advancedMaterial*`）留待无并行 Agent 时一次做完。
