## A. 必验 6 条

### A1 相机取景 / 解码（二维码发送 → 扫码 → 导入）

- **前置条件**：dev 包 ×2 台（同版本）或 1 台 + 另一台装 dev；相机权限「未授予」「已授予」各一轮；发送端至少 1 门课（可 设置→诊断→实时测试夹具 装 24 节夹具课）。
- **操作步骤**：
  1. 端 A 首页「更多」→ 数据传输 → 二维码发送（选「当前课表」）→ 出现二维码与「已发 N/M 帧」；
  2. 端 B 数据传输 → 扫码接收 → 首次弹相机权限 → 允许 → 预览出现；
  3. A 的码对着 B 扫 → B 进度前进 → 收齐 → 提示导入 → 确认 → 课程出现在 B；
  4. 反向：系统设置里关掉相机权限再进扫码页 → 看提示与「去设置」→ 从设置返回看是否自动复检。
- **预期**：预览有画面；识别到帧后进度按帧前进；收齐后提示明确；拒绝权限给说明 + 去设置、不白屏；返回后状态自动更新；退出扫码页相机指示灯灭。
- **不合格长什么样**：预览黑屏/绿屏；有画面但永远 0 帧（不解码）；进度跳帧/倒退/收齐不提示；拒绝后只有空白一直转圈；「去设置」点不动；退出后相机仍占用、再进黑屏；导入后课程不出现。
- **证据怎么留**：录屏（权限 → 预览 → 扫码 → 收齐 → 导入）+ 两张截图（发送页二维码、接收页进度）；失败再补「相机指示灯常亮 / 再进黑屏」。单台设备只能验权限 / 预览 /「无码不误报」，解码那半标「未验」。

### A2 WebDAV 上传 → 下载 → 冲突 → 恢复两步确认

- **前置条件**：坚果云账号 + 应用专用密码；**先在设置→高级里把远端文件夹改成独立目录**（如 `Apps/qingyu-sync-l4`），避免覆盖真实的云端快照；dev 包造 2–3 门可辨认的课；第二台设备或坚果云网页端（造冲突 / 下载用）。
- **操作步骤**：
  1. **上传**：云同步 → 连接（账号 + 应用密码，先「测试连接」）→ 立即同步 → 提示「已上传到云端」，网页端看到快照文件时间更新且含刚造的课；
  2. **下载**：另一台设备连同一文件夹 → 立即同步 → 提示「已从云端恢复」，课程与名称一致；
  3. **冲突**：端 A 改课不同步 → 网页端 / 端 B 上传另一份快照 → 端 A 点立即同步 → 弹「检测到同步冲突」→ 选「使用云端」本地变远端；再重造一次选「保留本机」上传覆盖；
  4. **恢复两步**：备份版本 → 点一条 → 详情（设备 / 来源 / 时间 / 内容）→ 恢复 → **第一步确认框带差异概要（新增 X / 覆盖 Y / 删除 Z）** → 点取消（数据一动不动，再点仍能开同样概要）→ 再确认 → 提示「已恢复到此备份」→ 备份区出现「撤销上次恢复」→ 点撤销 → 数据回到恢复前。
- **预期**：四动作各有明确提示；冲突必须停下来等用户选；恢复必须确认后才动数据，且概要数字与实际变化一致（如「新增 2 门」恢复后确实多 2 门）；同步方式下拉选中的就是你点的那个。
- **不合格长什么样**：点恢复直接覆盖（无概要 / 无二次确认）；取消后数据已变；概要数字对不上；冲突被静默覆盖，或「保留本机 / 使用云端」两个按钮做同一件事；同步方式下拉显示与选中错位（历史真 bug）；错误提示里出现完整密码或带账号的 URL；**本机数据为空时仍把空包上传覆盖云端**（最危险）。
- **证据怎么留**：每步一张截图（提示条 + 状态行）+ 坚果云网页端截图（文件时间 / 内容）+ 恢复前后课程数截图；恢复段录屏（恢复 → 取消 → 恢复 → 撤销）。

### A3 通知点击落页

- **前置条件**：通知权限允许（首启问一次；拒绝后到系统设置开）；确认在 dev 包操作。
- **操作步骤**：
  1. **最快路径**：数据传输 → 局域网编辑 → 开启 → 通知栏出现常驻「局域网编辑」→ 最近任务划掉（冷启动）→ 点通知；
  2. **后台路径**：再开一次 → Home 压后台 → 点通知；
  3. **考试提醒（可选）**：加一条考试 + 提醒「提前 1~2 分钟」→ 等通知 → 点；
  4. 点完后按返回；再旋转屏幕看是否重复弹出。
- **预期**：冷启动 / 后台两条都落到指定页（局域网编辑页 / 考试列表页）；落页后 extra 被消费（旋转、重建不重复推页）；返回回主屏；**周报 / 实时活动通知目前没有页面参数，点了只回主屏——属当前实现**（记一条「未接落点」，不算 ❌，除非产品要求落页）。
- **不合格长什么样**：点了只回主屏 / 闪一下没动；冷启动落页又被弹回主屏；落错页（考试提醒落设置）；通知点了打不开应用；同一页推两层，返回要点两次。
- **证据怎么留**：录屏（通知栏 → 点击 → 落页 → 返回）+ 截图（落页顶栏标题 + 通知条目）。

### A4 键盘不顶按钮

- **前置条件**：系统手势导航（三键导航再抽一条）；默认输入法。
- **操作步骤**：
  1. **学校适配详情**（`g2.adapterDetail`）：点自定义登录地址输入框 → 键盘弹起 → 看底部「在应用内打开登录页」是否完整可见可点；
  2. **云同步「连接」弹层**：账号 + 应用密码两框 → 看底部按钮与「弹层-键盘之间是否多一截空白」→ 收起键盘看是否回位；
  3. **加课 / 课程备注**：输入框聚焦后能否滚到下面的字段。
- **预期**：底部按钮始终完整可见；弹层被抬到键盘上方且只留约 16dp 呼吸；收起后恢复「导航栏 + 16dp」。
- **不合格长什么样**：按钮被键盘遮住点不到；弹层底部多出一大截空白（24–40dp）；收起后按钮被小白条压住半截；输入框在键盘下且页面滚不动。
- **证据怎么留**：三段 5 秒录屏 + 带键盘的截图；标注导航方式。

### A5 矮屏弹窗不裁切

- **前置条件**：手机横屏（或分屏 / 自由窗口），窗口高 < 600dp；可再叠一轮 1.3× 字体。
- **操作步骤**：横屏下逐个开：① 加课页「选择周次」弹层（限高 0.72）② 课程操作弹层（多行）③ 云同步「恢复到此备份」确认框（差异概要长文本）④ 学校导入对话框（0.75 / 0.6）⑤ 设置 → 节假日 → 高级（内部 380dp 列表）⑥ 任一下拉 / 日期选择器。每个：看标题 → 拖内容到底 → 看底部按钮。
- **预期**：标题完整；内容能滚到底且末行完整；取消 / 确认完整可见可点；圆角不与状态栏重叠；矮屏按「屏高 − 180dp」放宽（`QingyuAdaptiveRules.kt:88-124`）而不是硬留比例。
- **不合格长什么样**：标题被裁一半；底部按钮跑出屏幕 / 被手势条压住；内容截断且不可滚；弹层顶到状态栏、圆角被切；横屏后弹层重建丢内容。
- **证据怎么留**：每个弹层一张横屏截图 + 一次「拖到底」录屏；记机型与实际窗口高度（dp）。

### A6 课卡铃铛「已设提醒 + 取消」

- **前置条件**：dev 包里有今天 / 本周要上的课；**「已设提醒 + 取消」那半需要一份含 `classReminders` 的全量备份**（从旧正式版导出 `.mikcb`，再在 dev 包 数据传输 → 导入 → 覆盖 / 导入为新）。
- **操作步骤**：
  1. **负向**：干净数据下周视图 → 课卡右上角**没有**铃铛；
  2. **系统时钟半**：点课卡 → 操作弹层 →「这节课闹钟」→ 快捷 / 自定义 → 应跳系统时钟（或按跳过界面直接建）→ 回课卡仍**不该**有铃铛（当前实现只写系统时钟）；
  3. **正向（导入后）**：该课课卡右上角出现白底圆 + 主题色铃铛 → 点课卡 → 子弹层出现「已设提醒：HH:mm」+「取消」→ 点取消 → toast「已取消提醒」→ 铃铛消失 → 再进子弹层无已设行。
- **预期**：铃铛只在真有 `classReminders` 时亮；取消走共享逻辑（`ClassReminderLogic.remove`）并落盘（退出重进不复现）；同课同日不留两条。
- **不合格长什么样**：没设过也亮；设了系统闹钟就亮（口径混淆）；取消没反应 / 取消后铃铛还在 / 退出重进复活；提示文案错；同日出现两个铃铛。
- **证据怎么留**：课卡截图（有 / 无铃铛）、子弹层截图（含「已设提醒」与「取消」）、取消后课卡 + toast；一段录屏。
- **备注（真缺口）**：`ClassReminderLogic.upsert` 生产调用点 0 处，`ClassAlarmSheet` 三个动作只发 `AlarmClock.ACTION_SET_ALARM`（`ClassAlarmSheet.kt:43-62`、`SystemAlarm.kt:21-52`）——干净 dev 包里第 ③ 步造不出来，只能靠导入备份。

### A+ 同一点名的另外 3 条（简版，别漏）

- **宽屏 Rail**：平板横屏 / 分屏 ≥840dp 左侧 Rail（≥1200dp 展开带字）；点条目切换正常；返回手势不与 Rail 抢；内容列限宽 640dp 居中。

## C. dev 包不能代替正式包（applicationId 带 `.debug`，单独列）

### C.1 为什么替代不了（三条机制）

1. **数据目录不同**：dev 是 `com.mutx163.qingyu.debug`，与 `com.mutx163.qingyu` 两条独立私有目录。装 dev 不动正式数据，所以「覆盖安装 dev」只证明 dev 自己那份能留，**证明不了正式包那台机器上的旧数据能活**。
2. **dev 是干净安装，没有旧版遗留**：正式包要迁的是旧 Flutter 版的盘（单 `courses` 键、旧 `webdav_sync_password` 密文、旧通知渠道、已排闹钟）。dev 盘里根本没有这些，升级迁移路径在 dev 上无数据可迁。
3. **渠道差异**：dev 的 versionName 带 `-debug`、label「轻屿课表调试版」、UMENG_CHANNEL `official-debug`；签名、权限授予历史、通知渠道状态都不同，行为不能互推。
4. **附带风险**：dev 连的是**同一朵云端**。用真实坚果云账号在 dev 里同步，可能把空 / 测试数据上传覆盖真实快照——必须换远端文件夹或测试账号（A2 前置已写）。

### C.2 正式包额外要验（12 条）

| # | 项 | 判据 |
|---|---|---|
| 1 | **覆盖安装不卸载** | 课表 / 多档案 / 作息 / 课程 / 设置 / 壁纸 / 考试 / 任务 / 提醒 / 城市 / 底栏排列一条不丢 |
| 2 | 旧版 legacy 迁移 | 单 `courses` 键 → 默认档案；开学日 / 周次 / 语言随迁（`UpgradeScenarioTest` 格 1 口径） |
| 3 | WebDAV 密码迁移 | 旧 `webdav_sync_password` 密文键新版不认 → 应提示「重新输入应用专用密码」，不能静默失败 |
| 4 | 签名一致 | 正式包必须同发布 keystore，否则装不上（提示签名不一致） |
| 5 | 版本号 | versionCode = 150 + 100000 = 100150；versionName `3.0.0-0`（无 `-debug` / `-profile` 后缀）；从旧正式版升级不被判降级 |
| 6 | 已排通知 / 闹钟 | 升级后考试提醒、周报、实时活动、单节课提醒仍能触发；点击落页与 dev 同一套 |
| 7 | 通知渠道 | 旧渠道 ID 未被改（否则用户关过的渠道会「复活」或被重置） |
| 8 | 桌面小组件 | 已在桌面的组件不被移除（ComponentName 未变）、能刷新、点按进壳 |
| 9 | 外部入口 | 文件管理器打开 `.ics` / `.mikcb` / `.csv` / `.xlsx`、点 umeng scheme → 进壳并落到对应页（跳板 `ShellExternalEntryActivity`） |
| 10 | 真实云端 | 用真实数据上传一次，网页端确认快照是完整数据而非空包；再走一次两步恢复 |
| 11 | 外观继承 | 应用名 / 图标未变；语言、深色、字体缩放、底栏排列沿用 |
| 12 | 反面纪律 | **卸载重装不能用来验「不丢」**（会清数据）；要验不丢只能覆盖安装 |

## D. 建议执行顺序与耗时（按一次坐着能做完的量分批）

### D.1 准备（一次性，10–15 分钟）

- 出包：AS 选 **devDebug** 运行，或 `./gradlew :app:assembleDevDebug`；装手机（与正式包并存）。
- 首启授权：通知权限；相机在进扫码页时授。
- 造最小数据：3 门课（含 1 门今天）、1 个多课表、1 条考试（带提醒）、1 条任务、1 条日程；可选：含 `classReminders` 的备份（A6）、坚果云应用密码 + 独立远端文件夹（A2）。
- 记录表头：`页面 | 结论(✅/⚠️/❌) | 差在哪 | 证据文件 | 设备+方向`。

### D.2 三座（各一次坐着能做完）

| 座 | 内容 | 时长 |
|---|---|---|
| **第 1 座 · 版式与手感**（竖屏为主） | A4 键盘 → A5 矮屏（横屏约 10 分钟）→ A6 铃铛 → B1 课表 → B2 设置 → B6 关于 | 60–75 分钟 |
| **第 2 座 · 网络与外设**（需第二台设备 + 账号） | A1 相机 / 二维码 → A2 WebDAV → A3 通知 → B3 导入 → B9 同步备份 → B10 导出传输 | 45–60 分钟 |
| **第 3 座 · 正式包升级**（需旧正式包 + 真数据） | §C.2 的 12 条 | 30–45 分钟 |
| 余下可插空 | B4 统计、B5 实时活动、B7 日程任务、B8 作息考试、B11 诊断、B12 引导展示 | 25–30 分钟 |

**合计 2.5–3 小时（熟手）/ 4–5 小时（含摸索与重试）。**

### D.3 迷你版

- **只有 15 分钟**：周视图 + 底栏 + 深色壁纸 + 加课弹层（键盘 / 矮屏）——能抓「状态栏多一条空白 / 坞压内容 / 玻璃变灰块 / 白底白字 / 按钮被键盘顶」五类。
- **只有 1 小时**：A3–A6 + B1 课表 + B2 设置（每类挑 1 页）。

### D.4 提速工具（dev 包专属，可选）

- **深链直达**：`adb shell am start -a android.intent.action.VIEW -d "mikcb-debug:///settings/cloud-sync"` 这类，覆盖约 35 条路由（设置族、云同步、数据传输、诊断、展示册、关于、多课表…；映射表 `ShellWiring.kt:1462-1521`），**不是全部页面**；只在 `*.debug` / `*.profile` 生效。
- 索引没有搜索框，按批次分组往下翻；批次号（P3-A…）与本文一一对应。

### D.5 证据规范

- 截图：`L4-<区>-<pageId>-<方向>-<浅/深>.png`，如 `L4-B-b.general-V-dark.png`；录屏：`L4-A2-webdav-restore.mp4`。
- 每条结论必须能对应到一张图或一段录屏；❌ 的写清「差在哪 + 复现步骤」，避免「感觉不对」。

## E. 需要拍板 / 补做（按优先级）

1. **单节课提醒无写入入口**（A6）：`ClassReminderLogic.upsert` 生产调用点 0 处，UI 只发系统时钟 → App 内无法新建 `classReminders`，也就永远看不到「已设提醒 + 取消」。要么补写入，要么把该功能从「应验」降级为「仅升级数据可见」。
2. **正式包是否应出现「页面索引」**：`resolveDockIds` 无 flavor 门，prod 全新安装同样会追加 `index`（旧设置里已存过底栏排列则不会）。产品要决定是否加构建门。
3. **周报 / 实时活动通知无页面参数**：点了只回主屏（`WeeklyReportScheduler` / `LiveUpdateService` 未写 `open_route`）。要么补落点，要么明确为现状。
4. **文档债**：`PagesShellActivity` KDoc 仍写「包名带 `.ui` 后缀」；`ShellPageIndex` 的「二维码 / 相机缺依赖 → UNAVAILABLE」注释已过期；索引角标「演示数据」多数页已换成真宿主。
