## 3. 证据规范（不合规的结论一律作废）

- 每条结论：`文件:行号` + **原文片段**（≤15 行）+ 你跑的命令 + **真实输出**。
- 「没找到问题」也要给证据：你扫了什么、命令是什么、扫了多少文件。
- 推不出来的写「未验」并说明为什么（例如需要真机、需要用户点）。
- 不许写「看起来没问题 / 应该是对的 / 大致对齐」这类话。

## 4. 分级

- **P0**：用户点进去就能发现坏了或在骗人（死页、假成功、点了没反应、写不进去、回显不对）。
- **P1**：与 Dart 原版可见不一致（缺功能、版式/文案不对、自造行为）。
- **P2**：内部债（分层倒挂、模型层摆设、测试无牙、文档失真、注释过期）。

## 5. 硬规矩

- **只读产品代码**：不许改任何 `.kt` / `.dart` / `.arb` / 构建文件。你唯一的写作用域 = 你自己的报告文件。
- **不许跑 Gradle（L1/L2）**，不许跑 `scripts/test-kotlin-module.ps1`（JVM 闸门由 Lead 统一串行跑，避免 5 个 JVM 同时拉起来）。只许跑只读的 grep / read / 秒级脚本。
- 别人的在途改动（`git status` 里别人的 M/A/D）不改、不格式化、不提交。
- 报告写在指定的 `docs/plans/2026-10-29-quality-audit/<你的文件名>.md`，**只写这一个文件**。
