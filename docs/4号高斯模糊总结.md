# 4号高斯模糊总结

> **主题**：HyperOS 标题栏毛玻璃 — 最合适方案定稿  
> **前置**：[3号高斯模糊总结](./3号高斯模糊总结.md)（现状、根因、方案对比）  
> **相关代码**：`lib/ui/hyperos/frosted/`、`lib/services/frosted_blur_service.dart`、`lib/ui/hyperos/hyperos_page.dart`  
> **日期**：2026-07-06

---

## 1. 定稿结论（先读这段）

**最合适方案 = 两阶段 CFH（Two-Phase Content Frost Header）**

| 阶段 | 用户感受 | 技术动作 | 是否高斯模糊 |
|------|----------|----------|--------------|
| **滚动中** | 内容跟手指走（可略锐） | 缓存快照 + `scrollDelta` 裁条带 → **preview 优先显示** | **否** |
| **停手后** | 恢复毛玻璃质感 | 按需全屏重采 → 单次 blur → blur 优先显示 | **是** |
| **静止** | 稳定磨砂 | 沿用 `_blurredImage` + tint | **是** |

一句话：

> **滚动跟位置（轻量 crop），停手跟质感（单次 blur）。**  
> 不要用「每帧高斯模糊」追 60fps 滚动 — 这在 CFH 架构下做不到，也不该做。

---

## 2. 为什么不是别的方案

### 2.1 方案决策树

```
需要标题栏背后内容随滚动变化？
├─ 否 → tint-only（子页 overlayHeader:false、iOS/Web）✓ 维持现状
└─ 是 → 需要实时 GPU 采样？
    ├─ 是 → BackdropFilter
    │       └─ 列表页掉帧风险高 → ❌ 不作主方案
    └─ 否 → 快照 CFH
        ├─ 滚动中也 blur → 50–200ms/帧，追不上 + preview 被挡 → ❌ 当前痛点
        └─ 滚动 crop / 停手 blur → ✅ 两阶段 CFH（推荐）
```

### 2.2 各方案一句话否决理由

| 方案 | 否决 / 保留理由 |
|------|----------------|
| 实时 `BackdropFilter` | 全屏每帧 GPU 采样，设置页 `ListView` 易掉帧 |
| 只调 sigma / 节流 | `displayImage` 仍优先旧 blur，preview 白算 |
| 滚动中继续每帧 blur | Native RGBA 往返太重，快滑时 generation 丢弃，画面冻结 |
| 维持现状 | 体感已确认不合格 |
| 平台原生实时模糊 | 长期方向，短期与 Flutter 合成成本高 |
| **两阶段 CFH** | **跟手、性能、改动面、HyperOS 观感四维平衡最优** |

## 3. 推荐架构

### 3.1 数据流（定稿）

```
┌─────────────────────────────────────────────────────────────┐
│  RepaintBoundary（页面 body）                                │
│       │ postFrame                                          │
│       ▼                                                     │
│  [全屏 snapshot] ──缓存──► _rawFull + _captureScrollPixels │
│       │                                                     │
│       │ scrollDelta 裁条带（轻量，~5–15ms）                  │
│       ▼                                                     │
│  _previewImage ──滚动中 display 优先──► 标题栏 RawImage+tint │
│       │                                                     │
│       │ 仅 ScrollEnd + debounce 后一次                       │
│       ▼                                                     │
│  FrostedBlurService.blurImage（重，~50–150ms）              │
│       ▼                                                     │
│  _blurredImage ──静止时 display 优先──► 标题栏 RawImage+tint │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 显示状态机

```
                    ┌──────────────┐
         进入页面 ──►│   IDLE_BLUR   │  display: blurred ?? preview
                    └──────┬───────┘
                           │ ScrollStart
                           ▼
                    ┌──────────────┐
                    │ SCROLL_PREVIEW│  display: preview ?? blurred  ◄── 关键
                    │  不启动 blur  │
                    └──────┬───────┘
                           │ ScrollEnd + debounce(80–120ms)
                           ▼
                    ┌──────────────┐
                    │  SETTLE_BLUR  │  fullCapture(按需) + 单次 blur
                    └──────┬───────┘
                           │ blur 完成
                           ▼
                    ┌──────────────┐
                    │   IDLE_BLUR   │
                    └──────────────┘
```

### 3.3 核心 API 改动（`FrostedHeaderController`）

```dart
bool _isUserScrolling = false;

ui.Image? get displayImage {
  if (_isUserScrolling) {
    return _previewImage ?? _blurredImage;
  }
  return _blurredImage ?? _previewImage;
}

bool get isPreviewActive =>
    _isUserScrolling || (_blurredImage == null && _previewImage != null);
```

**滚动通知：**

```dart
void onScrollNotification(ScrollNotification n) {
  if (n is ScrollStartNotification) _isUserScrolling = true;
  if (n is ScrollEndNotification) {
    _scheduleIdleCapture(); // 内部 debounce 后 _isUserScrolling = false
  }
  // ScrollUpdate：仅 crop + _applyPreview，不调用 _blurStripAsync
}
```

**停手回调（debounce 结束后）：**

```dart
Future<void> _onScrollSettled() async {
  _isUserScrolling = false;
  await _updateHeaderBackdrop(
    source: 'scroll_idle',
    forceFullCapture: true,
    allowBlur: true, // 仅此路径允许 blur
  );
  notifyListeners();
}
```

**滚动中更新（`allowBlur: false`）：**

```dart
// _updateHeaderBackdrop 末尾：
_applyPreview(strip);
if (allowBlur && !_isUserScrolling) {
  unawaited(_blurStripAsync(...));
}
// 滚动中：notifyListeners 已在 _applyPreview 内触发
```

## 4. 与现有代码的衔接

### 4.1 保留不动的部分

| 模块 | 原因 |
|------|------|
| `FrostedCapture` 截屏 / 裁条带 | 逻辑正确，是两阶段的基础 |
| `FrostedBlurService` + `FrostedBlur.kt` | 停手后仍需要；sigma 缩放 `10 × 0.72` 正确 |
| `FrostedHeaderBackground` + tint 常量 | 视觉层不变；`previewTintBoost` 滚动时更有意义 |
| `hyperos_page.dart` 路由门控 / `_cfhReady` | 转场时 tint-only 仍然需要 |
| 页面分层（`overlayHeader`） | 产品范围已定义，不扩大 |

### 4.2 必须修的部分

| 问题 | 位置 | 修法 |
|------|------|------|
| 滚动时 preview 被挡 | `displayImage` getter | 见 §3.3 状态机 |
| 滚动中无意义 blur | `_updateHeaderBackdrop` | 加 `allowBlur` / `_isUserScrolling` 门控 |
| pending 等 blur 完成 | `_blurStripAsync` 末尾 | 滚动结束走独立 flush，不绑 blur 回调 |
| capture 锁阻塞 crop | `_isCapturingSnapshot` 分支 | 全屏 capture 与 crop-only **解耦**：锁只挡 capture，不挡 crop |
| bleed 在 blur 前被裁掉 | `cropHeaderStripFromSnapshot` | **先 blur 整条（含 bleed），再 `_cropTop` 到可见高度** |

### 4.3 bleed 裁切顺序（P1 画质）

当前：裁到 `visibleHeight` → blur → 底边 kernel 缺采样。  
定稿：

```
snapshot → crop(stripHeight = visible + bleed)
         → blur(整条)
         → cropTop(visibleHeight)
         → display
```

## 5. 页面与平台矩阵（不扩 scope）

| 页面 | `overlayHeader` | Android | iOS / Web |
|------|-----------------|---------|-----------|
| 设置首页 | `true` | 两阶段 CFH | tint-only |
| 设置子页 | `false`（默认） | tint-only | tint-only |
| 课表首页 | `false` | 实色标题栏 | 实色标题栏 |

**本期不为课表页 / 子页开启 overlay blur**，避免 push 时 `ListView` + overlay 的性能风险（见 `hyperos_page.dart` 注释）。

## 6. 参数定稿

| 参数 | 现值 | 定稿值 | 说明 |
|------|------|--------|------|
| `_scrollUpdateThrottle` | 16ms | **16ms** | 滚动 crop 目标 ~60fps |
| `_scrollFullThrottle` | 140ms | **100–140ms** | 全屏重采限频；lazy 列表补帧 |
| `_idleDebounce` | 200ms | **80–120ms** | 停手后更快进入 settle blur |
| `blurSigma`（逻辑） | 10.0 | **10.0** | 与 HyperOS 观感对齐 |
| `headerPixelRatio` | 0.72 | **0.72** | 停手 blur 可试 0.8，非必须 |
| `headerStripBleed` | 18 | **18–24** | blur 后裁切，底边不露硬线 |
| `previewTintBoost` | 0.12 | **0.12**（可试 0.14） | 滚动 sharp preview 的遮罩 |

## 7. 实施优先级

### P0 — 解决不跟手（必做，可独立上线）

1. `_isUserScrolling` + `displayImage` / `isPreviewActive` 状态机
2. 滚动路径：`crop` + `_applyPreview`，**禁止** `_blurStripAsync`
3. 停手路径：debounce → `forceFullCapture`（按需）→ **单次** blur
4. `_pendingUpdate` 在 `ScrollEnd` debounce 时 flush，不等待 blur

### P1 — 稳定性与画质

5. 全屏 capture 锁不阻塞 crop-only
6. bleed：blur 后再裁到可见高度
7. 合并重复 `ScrollNotification` 监听（`hyperos_page` vs `HyperosListView` 保留一处）

### P2 — 可观测与回归

8. 单测：`displayImage` 在 `SCROLL_PREVIEW` / `IDLE_BLUR` 下的优先级
9. 单测：滚动中 `blurImage` 调用次数为 0；停手后为 1
10. Debug：`[FrostedHeader] mode=scroll_preview|idle_blur` 日志

## 8. 验收标准（Android 真机 · 设置首页）

1. **慢滑跟手**：标题栏背后内容 **≤2 帧**随手指移动（允许无 blur、略锐）
2. **停手精修**：松手后 **≤120ms** 过渡到模糊 + tint，无「冻很久突然跳变」
3. **快滑 flick**：不应长期停在滑动前的模糊帧
4. **lazy 列表**：新 section 滚入标题栏区域，停手后内容与模糊一致
5. **性能**：滚动过程无「每帧 Native RGBA blur」导致的明显掉帧
6. **回归**：子页、课表页、路由转场 tint-only 行为不变

## 9. 长期演进（非本期）

| 方向 | 时机 | 说明 |
|------|------|------|
| GPU 轻量 box-blur shader | 停手 blur 仍慢时 | 比 RGBA 往返轻，比 BackdropFilter 可控 |
| Android 原生实时区域模糊 | 大版本 HyperOS 对齐 | 需评估 Flutter 纹理合成 |
| Debug Tuning 面板暴露 CFH 参数 | P2 后 | 便于真机调 `debounce` / `bleed` |
